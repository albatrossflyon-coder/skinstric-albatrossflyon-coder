**Real bug found by Chris (uploaded photo → error) — fixed 2026-07-04:** `/testing/camera` and `/testing/upload` were both storing the *entire* `skinstricPhaseTwo` response (`{success, message, data: {race, age, gender}}`) into `localStorage`, instead of unwrapping `.data`. Results page then tried to read `race`/`age`/`gender` directly off the wrapper object, got `undefined`, and crashed on `Object.entries(undefined)`. Fixed both save calls to destructure `const { data } = await res.json()`. Also hardened `sortedEntries` in the results page to return `[]` instead of throwing if a category is ever missing/malformed (external-API boundary, worth guarding). Verified with a real end-to-end run: generated a test image in-browser, pushed it through the real upload input via a `DataTransfer`-constructed `File` (no OS file picker needed), submitted through the actual `skinstricPhaseTwo` API, confirmed the results page renders the real returned demographics correctly with no console errors.

**2026-07-04 — Full `/code-review xhigh` pass (10-angle multi-agent review) on the whole session's uncommitted diff.** Found and fixed 5 real correctness bugs, 2 more flagged as plausible and fixed defensively:
- **`/testing/camera` — live video never actually displayed.** `stage` starts at `"starting"` and the `<video>` element only mounts once it leaves that state, but `startCamera()` assigned `srcObject` to `videoRef.current` *before* that mount happened (so it silently no-op'd on a null ref) and nothing ever reassigned it afterward. On any real device this would show a blank/black rectangle instead of the camera feed — this was a real regression from adding the "Setting up camera..." loading stage this session, and I hadn't caught it myself because this environment has no real webcam to exercise the success path (permission always fails instantly here). Fixed with a second effect that attaches the stream once `stage === "live"` and the video ref exists.
- **`/testing/camera` — Back button reloaded instead of navigating** whenever `stage` was `"starting"` (including the permission-denied case, since `stage` never advances past `"starting"` on failure) — the ternary only special-cased `"live"`. Fixed to only trigger `retake()` (reload) when `stage === "captured"`; every other state now navigates back to `/testing/select-analysis`. Verified live in-browser.
- **`/testing/results` — a missing category could crash the whole page.** `data[activeCategory][selectedLabel] ?? 0` accessed `data[activeCategory]` without optional chaining — if a category were ever missing from a malformed/partial API response (the same failure class as today's earlier unwrap bug), this throws instead of falling back like the rest of the page already does. Fixed to `data[activeCategory]?.[selectedLabel] ?? 0`. Verified live with deliberately incomplete mock data (missing `gender` entirely) — renders `—`/`0%` cleanly instead of crashing.
- **`/testing/intro` — Proceed button vanished (not just disabled) during the API call**, since its visibility class was driven by `canProceed` which also factors in `!loading`. Fixed to key visibility off `hasValue` alone, with a separate dimmed/disabled look while loading.
- **`/testing/intro` — validation error didn't clear while editing to fix it**, and **survived across step navigation** (Back to step 1 could show a stale error from step 2's API failure). Fixed both: `onChange` now clears `error`, and so does `handleBack`. Verified live: typed "Chris3" → "Name cannot contain numbers." appeared → deleted the digit → error cleared instantly.
- Also removed a genuinely dead `Step.placeholder` field in intro (never read; the input intentionally uses `step.question` as its placeholder to match the verified Figma design).
- Not fixed, flagged only as follow-up cleanup (architecture, not bugs): `DiamondIcon` is duplicated identically across all 6 rewritten pages, and the localStorage read/write pattern (key strings, JSON try/catch) is duplicated across 4 call sites with no shared hook. Worth a `components/DiamondIcon.tsx` and a small `useLocalStorage`-style util if there's time before submission, but not required.
